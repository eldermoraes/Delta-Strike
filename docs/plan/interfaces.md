## 1. Global conventions

### 1.1 Units
- Distances: **logical px** (canvas 160×210). Physics time: **seconds** (`dt = DS.C.DT = 1/60`). Animation/state time: **ticks** (1 tick = 1 update at 60 Hz).
- Angles/curves: none. Everything is rectangular and flat.

### 1.2 Coordinate system (normative)
- **World:** `worldX ∈ [0,160)` (≡ screenX; no horizontal scroll). **`worldY` grows UPWARD** (the player goes up the river ⇒ `player.y` only increases in flight).
- **Screen:** `screenY` grows downward, playfield `screenY ∈ [0,161]`.
- **Camera:** `cameraY` (float) = worldY of screen row 0. In `playing`: `cameraY = player.y + DS.C.PLAYER_SCREEN_Y` (recomputed after `Entities.update`). Frozen in `title/paused/dying/respawn/gameover` (in `respawn` already repositioned at the checkpoint).
- **Render integer:** all rendering uses `camInt = Math.round(cameraY)`, computed once per frame in `game.render()` and passed to `River.render` and `Entities.render`. No one else rounds the camera.
- Conversions: `screenY = camInt − worldY` · `worldY = camInt − screenY` · `screenX = worldX`.

### 1.3 Entity anchors and drawing (normative)
- Entities store position by the **CENTER** `(x, y)` in world floats.
- Every entity has **even** dimensions. It covers world rows `[y − h/2, y + h/2 − 1]` and columns `[x − w/2, x + w/2 − 1]`.
- Single drawing formula (screen top-left):
  ```
  sx = Math.round(x) - (w >> 1)
  sy = (camInt - Math.round(y)) - (h >> 1) + 1
  ```
  (the `+1` guarantees pixel-perfect bridge↔road alignment; ALWAYS use it, for everything).
- E.g.: player (14×12, center on screen row 134) ⇒ drawn on rows 129..140.

### 1.4 Animation frames
All periods in **ticks**: heli 8; generic explosion 8/frame (3 frames = 24); debris alternate every 8, live 60; player boom alternates every 4, lasts 48; bridge flicker alternates every 4, lasts 32; text blink 30 on / 30 off (`visible = ((tick / 30) | 0) % 2 === 0`).

### 1.5 Code rules
- IIFE skeleton per file (architecture §1.2), `'use strict'`, single namespace `window.DS`.
- Load/dependency order: `constants → sprites → audio → river → entities → game`.
- Forbidden: `Math.random()`, `console.log`, `setInterval`, `setTimeout` for game logic, fetch/CDN/network, ES modules, frameworks.
- Magic numbers: forbidden in `river.js`, `entities.js`, `game.js` (use `DS.C`). Documented exceptions: synthesis parameters in `audio.js` (follow the audio-spec literally) and pixel-maps in `sprites.js` (follow the visual-spec literally).

## 3. Boot and first gesture (exact sequence)

1. The browser loads `index.html`; scripts in the order `constants → sprites → audio → river → entities → game` (each only defines its namespace, **no DOM/audio side effects on load**).
2. The `load` event (inline script in index.html): calls `DS.Game.init()` and then registers `sw.js` (if `serviceWorker in navigator && window.isSecureContext`).
3. `DS.Game.init()` (wrapped in try/catch with `console.error(e); throw e;`):
   1. `seed = parseSeed(location.search)` (§7.2).
   2. Visible canvas `#screen` (`getContext('2d', { alpha: false })`); offscreen canvas 160×210 (`octx`, alpha false, `imageSmoothingEnabled = false`).
   3. `DS.Sprites.init();`
   4. `DS.Audio.init();` — only registers unlock listeners and reads `ds.muted`. **Does not create the AudioContext.**
   5. `DS.River.init(seed);`
   6. `DS.Entities.init(hooks);` (hooks §7.3)
   7. `Input.init(canvas);` (game-internal submodule)
   8. `resize();` + `resize`/`orientationchange` listeners → `resize()`.
   9. `visibilitychange` listener: if `document.hidden && state === 'playing'` → `togglePause()`.
   10. Sets up touch hints (§8.4), `enterTitle()`, `requestAnimationFrame(frame)`.
4. **First user gesture** (`pointerdown` | `touchend` | `keydown`, audio.js's own listeners with `capture: true`): audio.js creates the `AudioContext`, builds the master chain, generates the noise buffer, `resume()`, marks ready and removes the 3 listeners. Every sound function is a silent no-op before that.
5. Start (Enter / click / touchstart in `title`): `startRun()` → `DS.Audio.uiStart(); DS.Audio.startEngine();` `state = 'playing'`. Since the start is itself a gesture, audio is always unlocked here.

## 6. `js/river.js` — `DS.River` (owner: T4)

### 6.1 Public API (exact signatures)

```js
DS.River.init(seed)        // uint32; clears cache, stores seed. Once at boot; never in startRun.
DS.River.channelAt(worldY) // float ok; clamp to >= 0. -> Array of 1 or 2 intervals
                           // { xl:int, xr:int } (xl inclusive, xr exclusive), ordered
                           // by xl. CACHED ARRAY: the caller does NOT mutate or retain it between ticks.
DS.River.sectionAt(worldY)   // -> int = Math.max(0, Math.floor(worldY / DS.C.SECTION_LEN))
DS.River.sectionStartY(i)    // -> i * DS.C.SECTION_LEN
DS.River.bridgeY(b)          // -> b * DS.C.SECTION_LEN   (b >= 1)
DS.River.spawns(i)           // -> Array of SpawnRecord (cached, do not mutate), ordered
                             //    by increasing y; for i >= 1 the first is the 'bridge'.
DS.River.render(ctx, camInt) // draws the full playfield (rows 0..161): water, banks,
                             // road and decoration. camInt: INTEGER (game rounded it).
```

### 6.2 Deterministic generation (normative)

- Per section `i`: `rng = DS.U.mulberry32(DS.U.sectionSeed(seed, i))`, generated on demand and cached (`sections[i] = { chunks, spawns, decor }`). Pure function of `(seed, i)` — visit order does not matter.
- `chunks`: array of 150 entries; each entry is `[{xl,xr}]` or `[{xl,xr},{xl,xr}]` (island). `channelAt(worldY)`: `i = sectionAt(y)`, `c = floor((y − i*1200) / 8)`, returns `sections[i].chunks[c]`.
- **FIXED order of rng consumption per section** (any deviation breaks determinism): (1) geometry; (2) decoration; (3) depots; (4) enemies; (5) jets.

#### 6.2.1 Geometry (chunks 0..149)

Permanent invariants: `xl`,`xr` multiples of 4; width `xr−xl` a multiple of 8, ∈ the section's `[wMin, wMax]` (except forced zones: 64 and ramps); channel within `[8, 152]`; per chunk, each edge changes 0 or ±4 px (±8 only in the blocked-WIDEN case below).

- **Chunk 0 and chunk 149:** forced `{ xl: 48, xr: 112 }` (bridge band). This guarantees continuity between sections.
- **Chunks 1..5:** centered WIDEN +8/chunk: widths 72, 80, 88, 96, 104 (cx = 80).
- **Chunks 6..11:** straight 104 centered. (Chunks 0..11 = entity-free safe zone.)
- **Chunks 12..130:** repeat segments until filled; current state `(cx, w)`:
  1. `r = rngInt(rng, 6 + 3 + 2 + pShift + pIsland)`; type by accumulated ranges in the order STRAIGHT(6), NARROW(3), WIDEN(2), SHIFT(pShift), ISLAND(pIsland).
  2. Length: `len = 8 + rngInt(rng, 8)`; for ISLAND, `len = 20 + rngInt(rng, 16)`. Truncate so as not to pass chunk 130.
  3. SHIFT consumes 1 more roll: `dir = rngInt(rng, 2) ? 1 : −1`.
  4. Per-chunk effect:
     - `STRAIGHT`: nothing.
     - `NARROW`: if `w > wMin`: `xl += 4; xr −= 4` (w −8).
     - `WIDEN`: if `w < wMax`: try `xl −= 4; xr += 4`; if `xl−4 < 8`, then only `xr += 8` (if `xr+8 ≤ 152`, otherwise nothing); mirrored if `xr+4 > 152`.
     - `SHIFT`: `cx += 4*dir` if both new edges fit in `[8,152]`; otherwise nothing (for the rest of the segment).
     - `ISLAND`: only if `w ≥ 88` at the start of the segment (otherwise the whole segment becomes WIDEN). Freezes `(cx, w)`. `wiMax = min(w − 56, 48)` (multiple of 8; `w−56` already is). Island centered at cx: width `wi` = 8 on the 1st chunk, +8/chunk up to `wiMax`, plateau, −8/chunk down to 8, disappears. Descent ramp sized to finish within `len` (and never after chunk 130 — truncate the plateau). A chunk with an island ⇒ 2 intervals: `[{xl, cx−wi/2}, {cx+wi/2, xr}]`.
- **Chunks 131..148 (convergence):** per chunk: `cx += 4*sign(80−cx)` if `cx ≠ 80`; `w += 8*sign(64−w)` if `w ≠ 64` (same edge rules). By construction it converges by chunk 145 in the worst case; the remaining chunks stay straight 64@80.

#### 6.2.2 Decoration (fixed consumption)

`side = rngInt(rng,2)`; `cursor = 3`. Loop while `cursor ≤ 144`:
1. `t = rngInt(rng, 3)` → 0 tree, 1 house, 2 house+tree.
2. Placement at chunk `c = cursor`, side `side` (0 = left). Reference width `w` = 12 (tree) or 20 (house/combo). Conservative water edges over the 2 covered chunks: left: `L = min(xl(c), xl(c+1))` (of the FIRST interval); right: `R = max(xr(c), xr(c+1))` (of the LAST interval).
   - Left: `ax = L − 8 − w`; valid if `ax ≥ 0`.
   - Right: `ax = R + 8`; valid if `ax + w ≤ 160`.
   - Invalid ⇒ skip (without consuming extra rng).
3. `decor` record: house/tree with **world top-left** `{ sprite:'house'|'tree', x: ax, yTop: c*8 + 8 }` (occupies world rows `yTop .. yTop−8`). Combo: house at `(ax, yTop)` + tree at `(ax+10, yTop−10)`.
4. `cursor += 8 + rngInt(rng, 8)`; `side ^= 1`.

#### 6.2.3 Depots (nFuel; fixed consumption of 3 rolls per k)

For `k = 0 .. nFuel−1`: base target `c0 = 12 + round((k + 0.5) * 119 / nFuel)`.
1. `jit = rngInt(rng,17) − 8`; `c = clamp(c0 + jit, 12, 130)`.
2. `branch = rngInt(rng, 2)` (always consumed; used only if there are 2 intervals).
3. `roll = rng()` (always consumed).
4. Placement: y = `i*1200 + c*8 + 4`. Interval = intersection of the navigable intervals (same branch, chosen by `branch`: 0 = first, 1 = last) of chunks `c−1, c, c+1`. If `interW = ixr − ixl < 12 + 2*10` → try the other branch; if that also fails → **skip** this depot.
5. `maxDev = floor((interW − 12 − 20) / 2)`; `dev = floor(roll * (2*maxDev + 1)) − maxDev`; `x = round((ixl + ixr)/2) + dev`, snapped to px.

#### 6.2.4 Enemies (nEnemy; fixed consumption of 6 rolls per k)

For `k = 0 .. nEnemy−1`: target `c0 = 12 + round((k + 0.5) * 119 / nEnemy)`.
1. `jit = rngInt(rng,17) − 8` → `c = clamp(c0 + jit, 12, 130)`.
2. Gap: while a record (fuel or enemy) exists with `|chunk − c| < 5`, `c++`; if `c > 130`, mark as skipped (but consume the remaining rolls).
3. `typeBit = rngInt(rng,2)` (0 ship, 1 heli); `moveRoll = rng()`; `dirBit = rngInt(rng,2)`; `branch = rngInt(rng,2)`; `posRoll = rng()`.
4. Interval (intersection of chunks `c−1, c, c+1`, branch by `branch`, fallback the other branch). If type ship and `interW < 48` → becomes heli. Sprite width `sw` (24 or 16); if `interW < sw + 4` → skip.
5. `maxDev = floor((interW − sw − 4) / 2)`; `dev = floor(posRoll * (2*maxDev+1)) − maxDev`; `x = round((ixl+ixr)/2) + dev`; `y = i*1200 + c*8 + 4`.
6. `moving = moveRoll < (type==='heli' ? heliMove : shipMove)`; `dir = dirBit ? 1 : −1`.

#### 6.2.5 Jets (nJet; 2 rolls per k)

`c0 = 20 + round((k + 0.5) * 100 / nJet)`; `jit = rngInt(rng,11) − 5`; `c = clamp(c0+jit, 20, 120)`; `sideBit = rngInt(rng,2)`; `x = sideBit ? 168 : −8`; `dir = sideBit ? −1 : 1`; `y = i*1200 + c*8 + 4`; `moving = true`.

#### 6.2.6 SpawnRecord (River → Entities contract)

```js
{
  id:     'sNN-KK',    // NN = section index, KK = index in the final array
  type:   'bridge' | 'ship' | 'heli' | 'jet' | 'fuel',
  x:      int,         // CENTER in world px (jet: -8 or 168)
  y:      int,         // CENTER worldY (bridge: exactly sectionStartY(i))
  dir:    -1 | 1,      // 1 for fuel/bridge
  moving: bool         // false for fuel/bridge
}
```
Section `i ≥ 1` has exactly 1 `bridge` `{x: 80, y: sectionStartY(i)}`. Final array = ordered by increasing `y` (bridge naturally first); ids assigned after sorting.

### 6.3 `DS.River.render(ctx, camInt)` — normative algorithm

```
for sy from 0 to 161:
  w   = camInt - sy                    // world row (int)
  ivs = channelAt(w)
  land color = (sectionAt(w) % 2 === 0) ? GRASS_A : GRASS_B
  paint the whole row (x 0..159) with the land color
  paint each interval [xl, xr) with WATER
then, for each bridge b >= 1 with a visible band:
  syTop = camInt - b*SECTION_LEN - 8 + 1        // +1 = rule §1.3 (band aligns to the bridge); rows syTop .. syTop+15
  for r from 0 to 15 (sy = syTop + r, if 0 <= sy <= 161):
    color: r==0 or r==15 -> ROAD_DARK; r==7 -> YELLOW; else ROAD_LIGHT
    paint ONLY the land parts of the row (x outside the intervals of
    channelAt(camInt - sy))
finally, visible decoration: for each decor record with rows in the window,
  DS.Sprites.draw(ctx, sprite, 0, x, camInt - yTop)
```
Optimization allowed (group rows of the same chunk into larger fillRects) as long as the per-pixel result is identical.

### 6.4 River invariants
- `channelAt` ALWAYS returns ≥1 interval; single-channel width ∈ [32, 120] (in forced zones, 64..104); each island channel ≥ 28 px; edges multiples of 4.
- `channelAt(y)` for the same `y` always returns the SAME content (cache), in any call order, for the same seed.
- Chunks 0..11 and 131..149 of every section: no entity spawn records (except the `bridge` at chunk 0 — the `sectionStartY` row).
- Depots: the x span `[x−6, x+6)` is over water on ALL covered rows (guaranteed by the 3-chunk intersection) — invariant required by the sprite's hollow letters.
- Ships only in intervals with width ≥ 48.
- Zero `Math.random()`.

### 7.3 Hooks (Entities → Game; synchronous, inside `Entities.update`)

```js
{
  onScore(points, source),   // source: 'ship'|'heli'|'jet'|'fuel'|'bridge'
  onPlayerDeath(cause),      // game decides (cheat) and calls enterDying(cause)
  onBridgeDestroyed(b),      // int bridge index (metric; checkpoint is derived)
  onRefuel()                 // called EVERY TICK of player x live-depot overlap
}
```

`onScore` (normative implementation in game): if score is already at `SCORE_MAX`, ignore. `before = score; score = min(SCORE_MAX, score + points);` if `floor(before/10000) < floor(score/10000)` and `score < SCORE_MAX*` (extra lives stop at the cap): `lives = min(9, lives+1); DS.Audio.extraLife();`. If `score === SCORE_MAX` for the first time: persist hi-score immediately. (*exact rule: awards are given for crossed multiples ≤ 990000.)

### 7.4 Entities update order (normative)

`cameraTop = player.y + DS.C.PLAYER_SCREEN_Y`; `cameraBottom = cameraTop − 161`.

1. **Spawning:** while `sectionStartY(nextSection) ≤ cameraTop + SPAWN_AHEAD`: push `DS.River.spawns(nextSection)` into `pending` (a y-ordered queue) and `nextSection++`. Instantiate every `pending` record with `y ≤ cameraTop + SPAWN_AHEAD`; DISCARD (without instantiating) records with `y < cameraBottom` or bridges with `bridges[b].destroyed === true`. An instantiated bridge becomes/reuses `bridges[b] = { b, x:80, y, destroyed:false, boomT:-1 }` with `b = y / SECTION_LEN`.
2. **Player:** `x += steer * PLAYER_STEER_SPEED * dt`, clamp `[PLAYER_MIN_X, PLAYER_MAX_X]`. Speed target: `throttle > 0 → SPEED_MAX`, `< 0 → SPEED_MIN`, `0 → CRUISE`; approaches with `PLAYER_ACCEL` (going up) / `PLAYER_DECEL` (going down), no overshoot. `y += speed * dt`.
3. **Fire:** `fireCooldown −= dt`. If `input.fire && fireCooldown ≤ 0 && missiles.length < MISSILE_MAX_ONSCREEN`: create a missile `{ x: player.x, y: player.y + 9 }`, `fireCooldown = FIRE_COOLDOWN`, `DS.Audio.shoot()`.
4. **Missiles:** `y += (MISSILE_SPEED + player.speed) * dt; x += steer * PLAYER_STEER_SPEED * dt` (steered missile). Remove when it exits off the top: `y > cameraTop + 8`. Terrain does NOT remove a missile (R4).
5. **Enemies:** ship/heli with `moving`: `x += dir * SPEED_type * speedMult * dt`; at the bounds of the navigable interval of its y (constant!): if `x − w/2 < xl + 2` ⇒ `dir = 1`; if `x + w/2 > xr − 2` ⇒ `dir = −1` (with clamp). `speedMult = DIFFICULTY[min(sectionAt(y),7)].speedMult`. Heli advances `animT`. Jet: `x += dir * JET_SPEED * speedMult * dt`, ignores the river; remove if `x < −10 || x > 170`. Fuel: static.
6. **Culling:** an entity with `y < cameraBottom − CULL_BEHIND` is removed (does not re-arm).
7. **Collisions:**
   - Missile (2×6 full) × enemy/depot (sprite AABB − 1 px per side): removes both, creates explosions (table §7.5), `DS.Audio.explosionSmall()`, `hooks.onScore(SCORE_type, type)`.
   - Missile × non-destroyed bridge (64×16 − 1): `destroyed = true; boomT = 0`, `DS.Audio.explosionBig()`, `hooks.onScore(SCORE_BRIDGE,'bridge')`, `hooks.onBridgeDestroyed(b)`, removes the missile, schedules 4 explosions (§7.5).
   - Player (hitbox 12×10) × ship/heli/jet: the enemy explodes (as above, WITHOUT points) and `killPlayer('enemy')`.
   - Player × non-destroyed bridge: `killPlayer('bridge')`.
   - Player × live depot: does NOT kill; `hooks.onRefuel()` this tick.
   - Player × banks: 3 world rows `player.y − 5`, `player.y`, `player.y + 5`; in each, safe iff THERE EXISTS an interval with `xl ≤ player.x − 6` and `player.x + 6 ≤ xr`; any unsafe row ⇒ `killPlayer('bank')`.
8. **Animations:** explosions `t += dt` (remove after 24 ticks ⇒ becomes 1 debris record at the same center, except bridge explosions, see §7.5); debris `t += dt` (remove after 60 ticks); the bridge's `boomT` advances to 32 and stops.

### 7.5 Explosions and debris (normative positions, WORLD coords)

| Target | Explosions (centers) | Subsequent debris (centers) |
|---|---|---|
| heli / jet | 1 × at the entity center | 1 × at the same center |

### 7.7 `playing` update (normative order)

```
1. input = Input.poll()
2. edges: pausePressed -> togglePause(); mutePressed -> Audio.setMuted(!isMuted())
3. DS.Entities.update(DT, input)     // may fire onPlayerDeath -> enterDying
4. if state is still 'playing': cameraY = getPlayer().y + PLAYER_SCREEN_Y
5. fuel -= FUEL_DRAIN_PER_S * DT     // constant drain (after step 3's refuel)
6. if fuel <= 0: fuel = 0; DS.Entities.killPlayer('fuel')
7. audio: setEngineSpeed(v);
   refuel: if refuelingThisTick && fuel < FUEL_MAX && (tick % REFUEL_TICK_PERIOD === 0):
     refuelTick(fuel / FUEL_MAX)
   lowFuel: edges of (fuel/FUEL_MAX < 0.25) -> lowFuelAlarm(true/false)
8. tick++; mirror DS.Game.*; refuelingThisTick = false
```

### 7.8 Input (game.js-internal submodule)

`Input.init(canvas)` installs listeners; `Input.poll()` → `{ steer: -1|0|1, throttle: -1|0|1, fire: bool, startPressed: bool, pausePressed: bool, mutePressed: bool }` — the `*Pressed` are edge-triggered and consumed by the poll.

- **Keyboard** (`e.code`, listeners on window; `preventDefault()` on arrows/Space/Enter; ignore `e.repeat` on edges): ArrowLeft/Right → steer (both held ⇒ 0); ArrowUp/Down → throttle (+1/−1; both ⇒ −1); Space → fire; Enter → startPressed; KeyP → pausePressed; KeyM → mutePressed.
- **Touch** (`{passive:false}` listeners + `preventDefault()`):
  - Corners (only `playing`/`paused`, tested on touchstart in LOGICAL coords via the canvas bounding rect): top-left 24×24 ⇒ mutePressed; top-right 24×24 ⇒ pausePressed. These touches do not become steering/fire.
  - Steering zone: a touch started with `clientX < innerWidth * 0.6`; the first becomes the joystick (stores `x0,y0`); `dx = x−x0`, `dy = y−y0` CSS px.
    - Steer with HYSTERESIS (Revision 2026-07-10, mobile playtest feedback — "steers too much with a simple tap"): ENGAGES −1/+1 when `|dx| ≥ TOUCH_DEADZONE_X` (28); once engaged, keeps the sign while `|dx| ≥ TOUCH_STEER_RELEASE_X` (14) and the sign of `dx` does not flip; RELEASES (steer 0) when `|dx| < 14`; if `dx` crosses to the opposite side beyond 28, engages the new sign. Old values (single deadzone of 10) revoked.
    - Throttle without hysteresis: +1 if `dy ≤ −TOUCH_THROTTLE_DY` (36), −1 if `dy ≥ +36`, otherwise 0 (24 revoked; keeps the steer easier to engage than the throttle).
    - touchend/cancel zeroes steer and throttle. Extra touches in the zone are ignored.
  - Fire zone: ≥1 active touch started with `clientX ≥ innerWidth * 0.6` ⇒ fire = true.
  - Any touchstart ⇒ startPressed (consumed only in title/paused/gameover).
  - `mousedown` on the canvas ⇒ startPressed.
- Start* = `startPressed` (Enter, click or touch).

### 7.9 Entities/Game invariants
- No `Math.random()`; variants come from the SpawnRecords ⇒ same seed + same inputs = identical run.
- `bridges` survives `respawn` (destroyed bridges stay destroyed); ALL the rest re-arms from the cached spawns.
- Array removal by swap-remove; no unnecessary allocations per tick.
- `killPlayer` idempotent per tick; fuel death only in the game's step 6.
- Safe zone (chunks 0..11) guarantees respawn without an unfair death; no invulnerability.
