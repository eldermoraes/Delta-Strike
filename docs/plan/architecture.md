# DELTA STRIKE — Technical Architecture

> **Status:** normative specification. The implementer must NOT make design decisions on their own: anything not here is in `docs/plan/game-design.md`, `docs/plan/visual-spec.md` or `docs/plan/audio-spec.md`, always referenced as a `DS.C.NAME` constant.
>
> **Convention for the origin of constants:** `[ARCH]` = value fixed in THIS document (final). `[GD]` = value comes from the game-design. `[VS]` = value comes from the visual-spec. `[AS]` = value comes from the audio-spec.
>
> Language of the docs: English. Code, identifiers, file names and internal strings: **English**.

---

## 1. Overview

DELTA STRIKE is a faithful recreation of the gameplay/visuals/sound of River Raid (Atari 2600, 1982) with 100% original assets. It runs in desktop and mobile browsers, 100% offline (PWA), with no build step, no frameworks, no network.

**Technical pillars (pinned, not to be re-litigated):**

- HTML5 Canvas 2D + vanilla JavaScript, classic scripts (not ES modules), loaded in order in `index.html`.
- Single global namespace `DS` (window.DS). No other global.
- Logical resolution **160×210 px** drawn on an offscreen canvas and scaled to the visible canvas with nearest-neighbor.
- Playfield: screen rows `y = 0..161` (162 px). HUD: rows `y = 162..209` (48 px).
- Web Audio API, 100% synthesized sounds (TIA aesthetic), unlocked on the first gesture.
- Deterministic update at a fixed 60 Hz; river generated by a seeded PRNG (mulberry32) — same seed ⇒ same game.

### 1.2 Code conventions (mandatory)

Each `js/*.js` file follows exactly this skeleton:

```js
/* DELTA STRIKE — <module>.js */
(function () {
  'use strict';
  window.DS = window.DS || {};

  // ... module contents ...

  DS.ModuleName = { /* public API */ };
})();
```

- `'use strict'` in every file, inside the IIFE.
- `console.log` is forbidden in production. Only `console.error` is allowed (and `console.warn` for recoverable failures, e.g.: localStorage unavailable).
- `setInterval`/`setTimeout` are forbidden for game logic (only `requestAnimationFrame`). `setTimeout` is allowed only in non-game code (e.g.: fading hints via CSS is preferable).
- All mutable module state lives in local variables of the IIFE; the public API exposes functions and, when specified, read-only properties.
- Dependency (and load) order: `constants → sprites → audio → river → entities → game`. A module may only reference modules earlier in the order. `game.js` knows all of them; `entities.js` knows `C, U, Sprites, Audio, River`; `river.js` knows `C, U, Sprites`; etc.

## 2. Coordinate system and camera

### 2.1 Definitions

- **World:** coordinates in logical px. `worldX ∈ [0, 160)` (there is no horizontal scroll; worldX ≡ screenX). **`worldY` grows UPWARD** — the player goes up the river, so `player.y` only increases during flight.
- **Screen (playfield):** `screenY` grows downward, `screenY ∈ [0, 161]`.
- **Camera:** `cameraY` = worldY corresponding to screen row `screenY = 0` (top of the playfield).

### 2.2 Conversion formulas (normative)

```
screenY = cameraY - worldY          // world → screen
worldY  = cameraY - screenY         // screen → world
screenX = worldX                    // identical
```

Range of world visible in the playfield: `worldY ∈ [cameraY - 161, cameraY]`.

### 2.3 Entity anchor and rounding

- Every entity stores position by the **center** of the sprite: `(x, y)` floats.
- Drawing: `sx = Math.round(x - w/2)`, `sy = Math.round((cameraY - y) - h/2)`, where `{w,h} = DS.Sprites.size(name)`. Round only at draw time; the simulation uses floats.

### 2.4 Camera follows the player

The player stays fixed at screen row `DS.C.PLAYER_SCREEN_Y = 130` `[ARCH]` (VS may adjust ±4 px; if it does, only the constant changes):

```
cameraY = player.y + DS.C.PLAYER_SCREEN_Y
```

Recomputed every `PLAYING` update **after** `DS.Entities.update`. The world scroll is, therefore, exactly the player's vertical speed — there is no separate scroll speed. During `DYING`, `RESPAWN` (before repositioning), `PAUSED`, `GAMEOVER` and `TITLE` the camera does not move.

### 2.5 World start

- The river is defined for `worldY >= 0`. `DS.River.channelAt` with a negative argument returns the channel at `worldY = 0` (clamp).
- Player's initial position in a new game: `player.y = DS.C.PLAYER_START_Y` `[GD]` (recommendation: `31`, which places the base of the playfield exactly at `worldY = 0`). `player.x = 80` (center) `[ARCH]`.

## 3. Game loop

Implemented in `game.js`. `requestAnimationFrame` + **fixed timestep** with an accumulator. Direct render (no interpolation — at 160×210 with snapping to whole pixels, interpolation brings no benefit and would break the Atari look).

### 3.1 Constants `[ARCH]`

```js
DS.C.DT             = 1 / 60;   // s, fixed simulation step
DS.C.MAX_FRAME_DELTA = 0.25;    // s, clamp for tab in background
DS.C.MAX_STEPS      = 5;        // max updates per render frame
```

### 3.2 Reference code (normative)

```js
var last = 0, acc = 0;

function frame(now) {
  requestAnimationFrame(frame);
  if (!last) { last = now; return; }
  var delta = (now - last) / 1000;
  last = now;
  if (delta > DS.C.MAX_FRAME_DELTA) delta = DS.C.DT; // back from background: drop the lost time
  acc += delta;
  var steps = 0;
  while (acc >= DS.C.DT && steps < DS.C.MAX_STEPS) {
    update(DS.C.DT);          // deterministic, always with fixed DT
    acc -= DS.C.DT;
    steps++;
  }
  if (steps === DS.C.MAX_STEPS) acc = 0; // anti "spiral of death": drop the backlog
  render();                   // draws the current state onto the offscreen and blits
}
requestAnimationFrame(frame);
```

Rules:

- `update()` NEVER receives a variable delta. All physics uses `DS.C.DT`.
- A global tick counter `tick` (int, increments by 1 per update) exists in `game.js` and is used to blink texts (e.g.: visible when `(tick / 30 | 0) % 2 === 0` = 0.5 s on / 0.5 s off) and passed to anyone needing synchronized animation.
- `render()` runs 1× per rAF frame, even if `steps === 0`.

## 4. State machine

### 4.1 States and transitions

```
                 start*        (collision | fuel==0)
  TITLE ───────────────▶ PLAYING ───────────────▶ DYING
    ▲                     ▲   │ ▲                   │ timer DYING_TIME
    │                     │   ▼ │ (P/visib.)        ▼
    │        timer/start  │  PAUSED         lives>0 ? RESPAWN : GAMEOVER
    │                     │                    │ timer RESPAWN_TIME
    └────── GAMEOVER ◀────┴────────────────────┘  → PLAYING
```

`start*` = Enter on the keyboard, mouse click or any touchstart.

Constants: `DS.C.DYING_TIME` `[GD]` (~1.0 s), `DS.C.RESPAWN_TIME` `[GD]` (~0.8 s), `DS.C.GAMEOVER_TIME` `[GD]` (~4 s).

Canonical names (strings, exposed in `DS.Game.state`):
`'title' | 'playing' | 'paused' | 'dying' | 'respawn' | 'gameover'`.

### 4.2 What runs in each state (normative table)

| State | update (per tick) | render (per frame) | Accepted inputs |
|---|---|---|---|
| `title` | no simulation; only edge-inputs | `River.render` with `cameraY = DS.C.TITLE_CAMERA_Y` `[ARCH]`=161 (static river of section 0); logo; blinking text "PRESS START"; zeroed HUD | start → `startRun()`; M → mute |
| `playing` | Input → `Entities.update(DT, input)` → `cameraY` → fuel drain → checks (fuel≤0 → `Entities.killPlayer('fuel')`) → audio (engine/refuel/lowfuel) | `River.render` → `Entities.render` → HUD | arrows/touch, fire, P → paused, M |
| `paused` | nothing | same frozen frame (playfield+HUD) + blinking "PAUSE" text | P/start → playing; M |
| `dying` | `Entities.updateExplosions(DT)`; decrements `stateTimer`; on reaching zero: `lives > 0 ? enterRespawn() : enterGameOver()` | same as playing (world frozen, explosion animates) | M |
| `respawn` | decrements `stateTimer`; on reaching zero → playing | world already repositioned at the checkpoint; player blinks (visible if `(tick/6|0)%2===0`) | M |
| `gameover` | decrements `stateTimer`; on reaching zero OR start → `enterTitle()` | frozen frame + "GAME OVER" + final score centered | start, M |

### 4.3 Private transition functions in `game.js` (normative names)

```js
function enterTitle()            // stops audio loops, resets demo hud
function startRun()              // score=0, lives=DS.C.LIVES_START, fuel=DS.C.FUEL_MAX,
                                 // DS.River.init(seed) is NOT re-called (river is fixed per seed),
                                 // DS.Entities.startRun(DS.C.PLAYER_START_Y), state='playing',
                                 // DS.Audio.startLoop('engine')
function enterDying(cause)       // state='dying', stateTimer=DS.C.DYING_TIME,
                                 // DS.Audio.stopLoop('engine'); stopLoop('fuelLow'); stopLoop('refuel');
                                 // DS.Audio.play('explosionPlayer')
function enterRespawn()          // lives--, fuel=DS.C.FUEL_MAX,
                                 // checkpointY = DS.River.sectionStartY(DS.River.sectionAt(deathY)) + DS.C.RESPAWN_OFFSET [GD],
                                 // DS.Entities.respawn(checkpointY), cameraY recomputed,
                                 // state='respawn', stateTimer=DS.C.RESPAWN_TIME
function enterGameOver()         // state='gameover', stateTimer=DS.C.GAMEOVER_TIME, persists hiscore
function togglePause()           // playing ⇄ paused; on pause: DS.Audio.stopLoop('engine');
                                 // on return: DS.Audio.startLoop('engine')
```

Fidelity notes:

- **Lives:** the decrement happens in `enterRespawn`/before `enterGameOver` — i.e., when death is consummated. `enterDying` does not touch lives; the `lives > 0` check at the exit of `dying` uses the current value (if `lives` was 1 and the player died, `dying` → `gameover` and lives goes to 0 there).
  Normative implementation: at the end of `dying`, do `lives--; if (lives > 0) enterRespawnWithoutDecrement() else enterGameOver()`. In other words: **the decrement happens exactly once, at the end of `dying`**.
- **Checkpoint:** restarts at the start of the current section (behavior of the original). Fuel goes back to full `[GD]`. Score is kept.
- `visibilitychange` with `document.hidden === true` during `playing` calls `togglePause()`.

### 5.2 `DS.U` — pure utilities `[ARCH]` (live in constants.js)

```js
DS.U.mulberry32(seed)   // → function(): float [0,1). Normative implementation below.
DS.U.clamp(v, lo, hi)   // → number
DS.U.sectionSeed(seed, i) // → uint32: (seed ^ Math.imul(i + 1, 0x9E3779B1)) >>> 0
DS.U.aabb(ax, ay, aw, ah, bx, by, bw, bh) // → bool; center+dim boxes, world
```

`mulberry32` (normative, byte by byte):

```js
DS.U.mulberry32 = function (seed) {
  var a = seed >>> 0;
  return function () {
    a = (a + 0x6D2B79F5) >>> 0;
    var t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t = (t ^ (t + Math.imul(t ^ (t >>> 7), t | 61))) >>> 0;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
};
```

`aabb` (normative): receives centers and dimensions; returns
`Math.abs(ax - bx) * 2 < (aw + bw) && Math.abs(ay - by) * 2 < (ah + bh)`.

## 6. `js/sprites.js` — `DS.Sprites`

### 6.1 Data format (contract with the visual-spec)

Private data in the file, normative format:

```js
var DATA = {
  player: {
    palette: { Y: 'PLAYER_BODY', W: 'PLAYER_DETAIL' }, // char → key in DS.C.PALETTE
    frames: [
      [ '..YY..',    // frame 0 = straight. Each string = 1 row; chars = pixels;
        '.YYYY.',    // '.' = transparent. All rows of the frame have the same length.
        'YYYYYY' ],
      [ /* frame 1 = banked LEFT */ ],
      [ /* frame 2 = banked RIGHT */ ]
    ]
  },
  // ... other sprites
};
```

- Colors are never hex literals here: always keys of `DS.C.PALETTE` (single source of truth of the visual-spec).
- All frames of a sprite have the same dimensions.

### 6.2 Canonical sprite names (contract; pixels come from the visual-spec)

| name | frames | use |
|---|---|---|
| `player` | 3 (0=straight, 1=left, 2=right) | player's jet |
| `heli` | 2 (alternating rotor) | helicopter |
| `ship` | 1 | ship |
| `jet` | 1 (draw flipped via frame 1 if VS wants; otherwise 1) | enemy jet |
| `fuel` | 1 | FUEL depot |
| `bridge` | 1 | bridge (width = river span at the bridge row; VS defines) |
| `explosion` | N `[VS]` | explosion (used by any death) |
| `lifeIcon` | 1 | lives indicator in the HUD |
| `fuelGauge` | 1 | background of the E–F gauge |
| `fuelPointer` | 1 | gauge pointer |
| `logo` | 1 | "DELTA STRIKE" logo of the title screen |
| `font` | 1 per glyph (see 6.3) | bitmap font for texts/score |
| `decorTree`, `decorHouse` | 1 each | bank decoration `[VS]` |

### 6.3 Public API (exact signatures)

```js
DS.Sprites.init()
//   Pre-renders each frame of each sprite onto its own offscreen canvas
//   (document.createElement('canvas'), ctx without unnecessary alpha).
//   Must be called 1× by DS.Game.init() BEFORE any draw. Returns undefined.

DS.Sprites.draw(ctx, name, frame, x, y)
//   ctx: CanvasRenderingContext2D (the 160×210 offscreen)
//   name: string (table 6.2). frame: int (apply frame % frameCount).
//   x, y: TOP-LEFT corner in SCREEN px, integers (caller already converted/rounded).
//   Draws via drawImage of the pre-rendered canvas. Returns undefined.

DS.Sprites.size(name)        // → { w: int, h: int } (dimensions of frame 0)
DS.Sprites.frameCount(name)  // → int

DS.Sprites.drawText(ctx, text, x, y)
//   Draws text (string) with the bitmap font 'font', monospaced,
//   advance = DS.C.FONT_W + 1 px [VS]. Guaranteed minimum charset:
//   'A'–'Z', '0'–'9', ' ', '-', '.', '!' . Chars outside the charset are skipped
//   (advances without drawing). x,y = top-left corner of the first glyph.

DS.Sprites.textWidth(text)   // → int px (to center: x = (160 - w) >> 1)
```

There is no runtime tinting: color variations = distinct sprites/palette entries defined by the VS.

## 7. `js/audio.js` — `DS.Audio`

API contract (the synthesis — oscillators, envelopes, noise, frequencies — is in the audio-spec; the signatures and sound names below are fixed):

```js
DS.Audio.init()
//   Creates internal state; does NOT create the AudioContext yet (autoplay policy).
//   Reads persisted mute: localStorage['ds.muted'] === '1'. Returns undefined.

DS.Audio.unlock()
//   Creates/resumes the AudioContext. MUST be called inside a user
//   gesture handler (keydown/mousedown/touchstart). Idempotent. Returns undefined.

DS.Audio.play(name)
//   One-shot. name ∈ { 'shot', 'explosionEnemy', 'explosionPlayer',
//   'explosionBridge', 'extraLife' } [AS may add, not rename].
//   Silent no-op if muted or not unlocked.

DS.Audio.startLoop(name) / DS.Audio.stopLoop(name)
//   Continuous loops. name ∈ { 'engine', 'fuelLow', 'refuel' }.
//   startLoop is idempotent (does not stack); stopLoop of a stopped loop is a no-op.

DS.Audio.setEngine(throttle01)
//   throttle01: float 0..1 (normalized player speed:
//   (speed - SPEED_MIN) / (SPEED_MAX - SPEED_MIN)). Modulates the pitch of the 'engine' loop.

DS.Audio.setMuted(m)   // bool; persists in localStorage['ds.muted'] ('1'/'0'),
                       // mutes/restores master gain immediately
DS.Audio.isMuted()     // → bool
DS.Audio.stopAll()     // stops all active loops and one-shots
```

### 7.1 Event → sound map (normative; who calls)

| Event | Caller | Call |
|---|---|---|
| missile fired | entities | `play('shot')` |
| enemy destroyed | entities | `play('explosionEnemy')` |
| bridge destroyed | entities | `play('explosionBridge')` |
| player death (`enterDying`) | game | `play('explosionPlayer')` + stopLoops |
| game start / resume | game | `startLoop('engine')` |
| pause / death / gameover / title | game | `stopLoop('engine')` |
| every playing tick | game | `setEngine(throttle01)` |
| fuel < `FUEL_LOW_FRAC` (edges) | game | `startLoop('fuelLow')` / `stopLoop('fuelLow')` |
| refueling (edges; see §9.8) | game | `startLoop('refuel')` / `stopLoop('refuel')` |
| extra life gained | game | `play('extraLife')` |
| M pressed | game | `setMuted(!isMuted())` |

Separation rule: **entities calls `DS.Audio.play` directly only for instant SFX caused by it** (shot, enemy/bridge explosions); everything that depends on game state (engine, fuel, lives, player death) is the game's responsibility via hooks.

## 8. `js/river.js` — `DS.River`

### 8.1 River model

- The world is divided into **sections** of `DS.C.SECTION_LEN` px: section `i` covers `worldY ∈ [i·SECTION_LEN, (i+1)·SECTION_LEN)`.
- **Bridge `b`** (b ≥ 1) sits at `worldY = b·SECTION_LEN` (center row of the bridge). Section 0 (game start) has no bridge at y=0.
- Within a section, the river is **piecewise-constant**: slices ("strips") of `DS.C.RIVER_STEP` px in height; within a strip, the channel does not change (stepped edges, like on the Atari). Strips per section: `SECTION_LEN / RIVER_STEP` (the game-design MUST choose values with exact division).
- Each strip has 1 or 2 **navigable intervals**: `{ xl, xr }` with `xl` inclusive, `xr` exclusive, integers, `0 ≤ xl < xr ≤ 160`. Two intervals = island in the middle (ordered by ascending `xl`).
- At the bridge row, generation forces a **single, straight, centered channel** for a window of ±`DS.C.BRIDGE_FLAT` px `[GD]` (the bridge and the gray "road" cross the entire screen).

### 8.2 Deterministic generation

- The global `seed` (uint32) comes from `DS.Game` (URL `?seed=` or `DS.C.DEFAULT_SEED`).
- Each section is generated **on demand and in isolation**: `rng = DS.U.mulberry32(DS.U.sectionSeed(seed, i))`. Thus `channelAt` is a pure function of (seed, worldY) — regardless of the order in which the sections are visited.
- The generated section is cached in an object `sections[i] = { strips, spawns, decor }` where:
  - `strips`: array of arrays of intervals (index = strip within the section).
  - `spawns`: array of spawn records (§8.4), ordered by ascending `y`.
  - `decor`: array `{ sprite, x, y }` of bank decoration (trees/houses), world coordinates, for `River.render` itself to draw.
- **Continuity between sections:** the first strip of section `i` must match the last one of section `i−1`. Normative rule: every section begins and ends in "single centered channel of half-width `DS.C.RIVER_MAX_HALF`" (the bridge window forces this at the start; generation converges to it at the end). With that, sections are independent and still continuous.
- The walk algorithm for the channel's width/position (how much it varies per strip, when an island opens, etc.) is defined in the game-design (`docs/plan/game-design.md`, section "River generation"), using ONLY this section's `rng()` — never `Math.random()`. `Math.random()` is **forbidden across the whole project** (exception: none).

### 8.3 Public API (exact signatures)

```js
DS.River.init(seed)
//   seed: uint32. Clears the section cache, stores the seed. Returns undefined.
//   Called 1× by DS.Game.init(); NOT re-called on startRun (river fixed per session).

DS.River.channelAt(worldY)
//   worldY: number (float ok; clamp to >= 0).
//   → Array of 1 or 2 intervals { xl: int, xr: int } (xl incl., xr excl.),
//   ordered by xl. THE RETURNED ARRAY IS SHARED/CACHED:
//   the caller MUST NOT MUTATE it nor retain it between ticks.

DS.River.sectionAt(worldY)      // → int: Math.max(0, Math.floor(worldY / DS.C.SECTION_LEN))
DS.River.sectionStartY(i)       // → number: i * DS.C.SECTION_LEN
DS.River.bridgeY(b)             // → number: b * DS.C.SECTION_LEN  (b >= 1)

DS.River.spawns(i)
//   i: int section index. → Array (cached, do not mutate) of spawn records (§8.4).

DS.River.render(ctx, cameraY)
//   Draws the ENTIRE background playfield (rows 0..161): water, banks,
//   steps, islands, road strip at the bridge rows, and decor.
//   Normative algorithm: for each screenY from 0 to 161:
//     worldY = cameraY - screenY; ivs = channelAt(worldY);
//     fillRect of the whole row with PALETTE.GRASS; then fillRect of each
//     interval with PALETTE.WATER; if |worldY - bridgeY(b)| <= ROAD_HALF [VS]
//     for some b, paint the land parts with PALETTE.ROAD.
//   Then draws the visible decor via DS.Sprites.draw.
//   (Optimization allowed: group rows of the same strip into a larger fillRect.
//    The per-pixel result must be identical to the algorithm above.)
```

### 8.4 Spawn record (River → Entities contract)

```js
{
  id:   'sNN-KK',        // unique string: NN = section, KK = index in the array
  type: 'ship'|'heli'|'jet'|'fuel'|'bridge',
  x:    int,             // center, world px (jet: entry x, 0 or 160)
  y:    number,          // center, worldY  (bridge: exactly bridgeY(b))
  dir:  -1|1,            // initial horizontal direction
  v:    float            // raw rng() [0,1) — entities uses it for variants
                          // (e.g.: v < DS.C.ENEMY_MOVE_CHANCE ⇒ spawns moving)
}
```

- Each section `i ≥ 1` contains exactly 1 record `type:'bridge'` with `y = sectionStartY(i)` — it is the **first** of the array. Quantities/positions of the others: game-design.
- River guarantees: `ship`/`heli`/`fuel` spawns have `x` inside a navigable interval at their `y`; `jet` has `x ∈ {0, 160}`.

## 9. `js/entities.js` — `DS.Entities`

### 9.1 Internal state

```js
var player;        // { x, y, speed, bank(-1|0|1), alive, fireCooldown }
var enemies = [];  // { rec, type, x, y, dir, moving, animT, alive }
var missiles = []; // { x, y }  (of the player; enemies do not shoot — faithful to the original)
```

Arrays with removal by swap-remove (`arr[i] = arr[arr.length-1]; arr.pop()`), no per-tick allocation beyond the unavoidable.

### 9.2 Public API (exact signatures)

```js

//   hooks: object §9.3 (all functions mandatory). Returns undefined.

DS.Entities.startRun(startY)
//   New game: clears enemies/missiles/explosions/bridges/pending,
//   nextSection = 0, creates player at (80, startY), speed = DS.C.PLAYER_SPEED_CRUISE,
```

### 9.3 Hooks (Entities → Game contract; synchronous calls during update)

```js
{
  onScore(points, source),      // source ∈ 'ship'|'heli'|'jet'|'fuel'|'bridge'
  onPlayerDeath(cause),         // game does enterDying(cause)
  onBridgeDestroyed(b),         // int bridge index (metric/implicit checkpoint)
  onRefuel()                    // called EVERY TICK the player is
                                // overlapping a live depot (game adds fuel)
}
```

### 9.4 Update order (normative)

1. **Spawning by advance:** while `sectionStartY(nextSection) <= cameraTop + SPAWN_AHEAD` (where `cameraTop = player.y + PLAYER_SCREEN_Y`), push `DS.River.spawns(nextSection)` into `pending` and `nextSection++`. Then, instantiate every record of `pending` with `y <= cameraTop + SPAWN_AHEAD` (bridges become/reuse `bridges[b]`; the others become enemies).
2. **Player:** `bank = sign(steer)` with simple hysteresis (|steer| < 0.3 ⇒ 0); `x += steer * PLAYER_STEER_SPEED * dt`, clamp `[PLAYER_MIN_X, PLAYER_MAX_X]`; `speed += throttle * PLAYER_ACCEL * dt`, clamp `[SPEED_MIN, SPEED_MAX]`; `y += speed * dt`.
3. **Shot:** `fireCooldown -= dt`; if `input.fire && fireCooldown <= 0 && missiles.length < MISSILE_MAX_ONSCREEN`: create a missile at `(player.x, player.y + h/2)`, `fireCooldown = FIRE_COOLDOWN`, `DS.Audio.play('shot')`.
4. **Missiles:** `y += MISSILE_SPEED * dt`. Remove if `screenY < -8` OR if the center `x` is not inside any interval of `channelAt(y)` **and** also does not overlap a bridge (missile dies at the bank — steps block the shot, faithful to the original).
5. **Enemies:** `ship`/`heli` with `moving=true` walk `x += dir * SPEED_type * dt`; upon touching the edge of their navigable interval (`x - w/2 < xl` or `x + w/2 > xr`), invert `dir` (clamp at the edge). `heli` alternates frame every `DS.C.HELI_ANIM_TIME` `[VS]`. `jet` crosses the screen ignoring the river; removed when leaving (`x < -8 || x > 168`). `fuel` is static.
6. **Culling:** an enemy with `y < cameraBottom - CULL_BEHIND` (where `cameraBottom = cameraTop - 161`) is removed and NOT re-armed.
7. **Collisions** (§9.6/9.7): missiles × (enemies, bridges); player × (banks, enemies, bridges, fuel).
8. **Explosions:** `t += dt`; frame = `floor(t / EXPLOSION_FRAME_TIME)`; remove when frame ≥ `frameCount('explosion')`.

### 9.5 Determinism

No `Math.random()` in entities. Variants come from `rec.v`. Behaviors depend only on state + input ⇒ replay with the same seed + same inputs is identical.

### 9.6 AABB collisions

- Collision box = sprite `{w,h}` shrunk: `cw = w - 2*HITBOX_SHRINK`, `ch = h - 2*HITBOX_SHRINK` (game-design may specialize per type with `DS.C.HITBOX.<type>`; in its absence, uses the global `HITBOX_SHRINK`).
- Test: `DS.U.aabb(...)` with centers.
- Missile = point (1×2 px) against the target's box.
- Result missile×enemy: remove both, create explosion at the enemy, `DS.Audio.play('explosionEnemy')`, `hooks.onScore(SCORE_type, type)`.
- Missile×bridge (only if `!destroyed`): `hp--`; if `hp <= 0`: `destroyed = true`, explosion at the center of the bridge, `DS.Audio.play('explosionBridge')`, `hooks.onScore(SCORE_BRIDGE,'bridge')`, `hooks.onBridgeDestroyed(b)`.
- Player×enemy (ship/heli/jet): `killPlayer('enemy')` (the enemy also explodes).
- Player×non-destroyed bridge: `killPlayer('bridge')`.
- Player×live fuel: does NOT kill; fires `hooks.onRefuel()` this tick (§9.8). Missile×fuel destroys the depot (explosion + `onScore(SCORE_FUEL,'fuel')`) — faithful to the original: you can score by blowing up the depot, even while refueling.

### 9.7 Player × banks collision (normative)

Sampling at 2 world rows: `yTop = player.y + ch/2` and `yBot = player.y - ch/2`. For each row: obtain `ivs = channelAt(row)`; the player is safe on this row if **there exists an interval** with `xl <= player.x - cw/2` and `player.x + cw/2 <= xr`. If any row fails ⇒ `killPlayer('bank')`. (Two samples suffice because `RIVER_STEP > ch`; the game-design guarantees this.)

### 9.8 Refueling (protocol with the game)

- Entities calls `hooks.onRefuel()` every overlap tick.
- Game: adds `REFUEL_PER_S * DT` to fuel (clamp at `FUEL_MAX`) and marks `refuelingThisTick = true`. At the end of the tick, compares with the previous tick: false→true transition ⇒ `DS.Audio.startLoop('refuel')`; true→false ⇒ `DS.Audio.stopLoop('refuel')`.

## 11. Input (internal submodule of `game.js`)

Not exposed in `DS.*` (except via `DS.Game` for debug: optionally `DS.Game.input` mirroring the last snapshot). Lives as a local `Input` object inside game.js's IIFE.

### 11.1 Internal API

```js

                     //     startPressed: bool, pausePressed: bool, mutePressed: bool }
                     // *Pressed are edge-triggered: true only on the first poll
                     // after the event (consumed by the poll).
```

### 11.2 Keyboard

| Key (`e.code`) | Action |
|---|---|
| `ArrowLeft` / `ArrowRight` | steer = −1 / +1 (holding) |
| `ArrowUp` / `ArrowDown` | throttle = +1 / −1 (holding) |
| `Space` | fire = true (holding; autofire via FIRE_COOLDOWN) |
| `Enter` | startPressed (edge) |
| `KeyP` | pausePressed (edge) |
| `KeyM` | mutePressed (edge) |

- `keydown`/`keyup` on `window`. `e.preventDefault()` for: the 4 arrows, `Space`, `Enter` (avoids scrolling/the page). Ignore `e.repeat` for the edges.
- First `keydown` of any mapped key → `DS.Audio.unlock()`.
- Simultaneous left/right keys: the last key pressed wins (store the order, do not add).

### 11.3 Touch (multi-touch by `identifier`)

Listeners on `window` with `{ passive: false }`; `e.preventDefault()` on touchstart/touchmove/touchend (together with CSS `touch-action: none`, eliminates scroll/zoom).

- **Left zone** (`touch.clientX < window.innerWidth / 2`): virtual joystick **relative to the initial touch point**. Store `{ id, x0, y0 }`. On each move of the same id: `dx = x - x0`, `dy = y - y0` (CSS px);
  `steer = clamp(dz(dx) / DS.C.TOUCH_JOY_RADIUS, -1, 1)` and
  `throttle = clamp(-dz(dy) / DS.C.TOUCH_JOY_RADIUS, -1, 1)`,
  where `dz(v) = (|v| <= DS.C.TOUCH_DEADZONE) ? 0 : v - sign(v)*TOUCH_DEADZONE`.
  Dragging up accelerates (negative dy ⇒ positive throttle). touchend/touchcancel of the id ⇒ steer=throttle=0. Only 1 steering touch at a time (the first; extra touches in the left zone are ignored).
- **Right zone**: fire = true while there is ≥1 active touch in the right zone (track ids). Autofire results from the FIRE_COOLDOWN in entities — cadence identical to holding Space.
- **Start:** any `touchstart` (any zone) also sets `startPressed` — consumed only in the title/gameover/paused states, so it does not interfere with the game.
- Every `touchstart` and `mousedown` → `DS.Audio.unlock()`.
- Mouse: `mousedown` on the canvas sets `startPressed` (for desktop clicking on PRESS START). The mouse does not control the game.

### 11.4 Touch visual hints

Two `<div class="hint">` in the HTML (§15): left "DRAG TO STEER", right "TAP TO FIRE" `[ARCH]`. Rules:

- Shown only if the device has touch (`'ontouchstart' in window || navigator.maxTouchPoints > 0`) — otherwise `display:none` via JS on init.
- They appear when the state enters `playing` for the first time in the session; each receives the `hidden` class (CSS `opacity:0` with `transition: opacity .5s`) when the corresponding gesture happens for the 1st time (steer ≠ 0 / fire) OR after 6 s.
- `pointer-events: none` always; they never block the game. They do not persist in localStorage (reappear per session).

## 12. Scale and presentation

### 12.1 Resize algorithm (normative)

```js
function resize() {
  var vw = window.innerWidth, vh = window.innerHeight;
  var dpr = window.devicePixelRatio || 1;
  var s = Math.floor(Math.min(vw * dpr / DS.C.LOGICAL_W, vh * dpr / DS.C.LOGICAL_H));
  if (s < 1) s = Math.min(vw * dpr / DS.C.LOGICAL_W, vh * dpr / DS.C.LOGICAL_H); // fractional only if integer does not fit
  canvas.width  = Math.round(DS.C.LOGICAL_W * s);
  canvas.height = Math.round(DS.C.LOGICAL_H * s);
  canvas.style.width  = (canvas.width  / dpr) + 'px';
  canvas.style.height = (canvas.height / dpr) + 'px';
  vctx = canvas.getContext('2d', { alpha: false });
  vctx.imageSmoothingEnabled = false;   // reset when width changes — always re-set
}
```

- Integer scale **in physical pixels** (multiplies by dpr before the floor) ⇒ crisp on retina screens.
- Centering and letterbox: via CSS flexbox on the body (§15.2), black body.
- Blit per frame: `vctx.drawImage(off, 0, 0, canvas.width, canvas.height)` with smoothing off = nearest-neighbor.
- Orientation: works in any (the algorithm only depends on vw/vh); the manifest requests portrait (§13.1).

```js
var CACHE = 'delta-strike-v1';   // manual bump on each release: -v2, -v3…
```

## 14. Icons — `tools/make_icons.py`

Development script (runs 1× to generate `icons/icon-192.png` and `icons/icon-512.png`), **stdlib only** (`zlib`, `struct`). Normative process:

1. Pixel-art grid 16×16 (below), 4-color palette.
2. Nearest-neighbor upscale: ×12 → 192×192; ×32 → 512×512.
3. Manual 8-bit RGBA PNG writing: PNG signature; `IHDR` chunk (width, height, bit depth 8, color type 6); `IDAT` = `zlib.compress` of the scanlines, each prefixed with filter byte `0`; `IEND`. CRC of each chunk via `zlib.crc32(type + data)`.

Normative grid and palette (`.`=black background, `B`=water, `Y`=jet, `O`=exhaust):

```
ICON = [
  "...BBBBBBBBBB...",
  "...BBBBBBBBBB...",
  "...BBBBYYBBBB...",
  "...BBBBYYBBBB...",
  "...BBBYYYYBBB...",
  "...BBBYYYYBBB...",
  "...BBYYYYYYBB...",
  "...BBYYYYYYBB...",
  "...BYYYYYYYYB...",
  "..YYYYYYYYYYYY..",
  ".YYYYYYYYYYYYYY.",
  ".YY..BYYYYB..YY.",
  "...BBBBOOBBBB...",
  "...BBBBOOBBBB...",
  "...BBBBBBBBBB...",
  "...BBBBBBBBBB...",
]
PAL = { '.': (0,0,0,255), 'B': (42,82,164,255),
        'Y': (232,210,88,255), 'O': (216,100,32,255) }
```

The hex of `B`/`Y`/`O` must be synchronized with `DS.C.PALETTE` (WATER, PLAYER_BODY, EXPLOSION) when the visual-spec fixes the NTSC values — update `PAL` and regenerate. The icon background stays pure black.

Reference implementation (normative; the implementer may copy it):

```python
#!/usr/bin/env python3
"""Generate icons/icon-192.png and icons/icon-512.png. Stdlib only."""
import struct, zlib, os

ICON = [  # 16x16, see architecture.md §14
    "...BBBBBBBBBB...", "...BBBBBBBBBB...", "...BBBBYYBBBB...",
    "...BBBBYYBBBB...", "...BBBYYYYBBB...", "...BBBYYYYBBB...",
    "...BBYYYYYYBB...", "...BBYYYYYYBB...", "...BYYYYYYYYB...",
    "..YYYYYYYYYYYY..", ".YYYYYYYYYYYYYY.", ".YY..BYYYYB..YY.",
    "...BBBBOOBBBB...", "...BBBBOOBBBB...", "...BBBBBBBBBB...",
    "...BBBBBBBBBB...",
]
PAL = {'.': (0,0,0,255), 'B': (42,82,164,255),
       'Y': (232,210,88,255), 'O': (216,100,32,255)}

def chunk(tag, data):
    return (struct.pack('>I', len(data)) + tag + data
            + struct.pack('>I', zlib.crc32(tag + data) & 0xFFFFFFFF))

def write_png(path, size):
    scale = size // 16
    raw = bytearray()
    for row in ICON:
        line = bytearray()
        for ch in row:
            line += bytes(PAL[ch]) * scale
        raw += (b'\x00' + bytes(line)) * scale   # filter 0 per scanline
    ihdr = struct.pack('>IIBBBBB', size, size, 8, 6, 0, 0, 0)
    png = (b'\x89PNG\r\n\x1a\n' + chunk(b'IHDR', ihdr)
           + chunk(b'IDAT', zlib.compress(bytes(raw), 9)) + chunk(b'IEND', b''))
    with open(path, 'wb') as f:
        f.write(png)
    print('wrote', path)

if __name__ == '__main__':
    out = os.path.join(os.path.dirname(__file__), '..', 'icons')
    os.makedirs(out, exist_ok=True)
```

## 16. Debug and testability

- `window.DS` is the global namespace — everything inspectable in the console.
- Guaranteed reads: `DS.Game.state`, `.score`, `.lives`, `.fuel`, `.cameraY`, `.seed`, `.tick` (§10.1); `DS.Entities.getPlayer()`; `DS.River.channelAt(y)`.
- `DS.Game.cheat.invincible = true` in the console to cross the game in tests (does not affect death by fuel).
- **`?seed=`**: `parseSeed`:

```js
function parseSeed(search) {
  var v = new URLSearchParams(search).get('seed');
  if (v === null) return DS.C.DEFAULT_SEED;
  var n = Number(v);            // accepts decimal and '0x...' hex
  return (isFinite(n)) ? (n >>> 0) : DS.C.DEFAULT_SEED;
}
```

- Determinism tests in the console:
  - `JSON.stringify(DS.River.channelAt(5000))` identical between reloads with the same seed.
  - `DS.River.spawns(3)` identical between reloads.
- No test framework: validation by checklist (§17) + manual smoke tests. No residual `console.log` (grep before release).
